# 热点选题与发布

## 零、这套东西的边界，先说清楚

- **热点是真抓的**。主源 xxapi（微博/抖音/B站/百度四个全通），备源 60s 只兜底。
  抓不到就 `ok=false` 并说明原因，**绝不返回示例热搜**。所以看到空榜单，
  正确反应是「这个源现在抓不到」，不是「补几条凑数」。
- **发布要登录，登录得人来**。扫码/验证码这一关脚本做不了，硬做只会把号搞风控。
  `publish_center action=login` 会把页面开出来，让用户扫一次，状态留在独立 profile 里。
- **发布不可撤回**。发出去的抖音/小红书只能删，删了还掉权重。
  所以 `run` 默认 dry-run：填完停在发布按钮前、截一张图。**加 exec=1 才算真发**。
  用户没明确说「发出去」，就永远别加 exec=1。

## 一、选题：从热搜里找能拍的

```
hotspot action=board platforms=weibo,douyin,bilibili limit=20
hotspot action=ideas platforms=weibo,douyin keywords=你的赛道 n=3
```

`ideas` 返回的每条带 `angle`（怎么切）和 `format`（竖屏短视频 / 图文或短口播）。
挑的时候按这三条过滤，能砍掉八成不能拍的：

1. **有具体的人或场景**。抽象名词（某政策、某概念）很难拍；「某个村、某个人、
   某个东西」才有画面。
2. **有冲突或反差**。能一句话说清谁跟谁不对付、什么跟什么预期不符。
3. **你自己能补上别人没有的一层**。全网都在转述时，你去拍一个现场、
   找一个当事人、做一次实测 —— 这才是二创，不是搬运。

热度高只说明看的人多，不代表你能拍。**热度 × 可拍性 × 你的独特视角**，三者都要。

## 二、出片之后第一件事：规格预检

各平台硬上限（`publish_kit.PLATFORMS`，超了会被前端直接截断，不报错）：

| 平台 | 标题上限 | 正文 | 话题 | 画幅 |
|---|---|---|---|---|
| 抖音 | 30 字 | 1000 | 3-5 个 | 9:16 |
| 小红书 | 20 全角 | 1000 | ≤10 | 3:4 或 9:16 |
| 快手 | 500 字 | 1000 | — | 9:16 |
| 视频号 | 22 字 | 1000 | — | 9:16 |
| B站 | 80 字 | 2000 | — | 16:9 |

```
publish_center action=check platform=抖音 title=… body=… tags=… aspect=9:16
```

**画幅方向反了最要命**：抖音给 16:9 会被上下裁掉一半，人脸直接切掉额头。
`check` 会明确报「方向反了会被裁切」，别忽略这句。

标题超限不要自己缩字到语义不通 —— 换一个更短的表达，或者把细节挪进正文第一行。

## 三、发布：先演练，看图，再真发

```
# 第一步：只填不发
publish_center action=run platform=xiaohongshu video=/绝对/路径.mp4 \
  title=… body=… tags=AI,剪辑 exec=0
→ 回 screenshot_url，界面直接显示截图

# 第二步：用户确认后
publish_center action=run … exec=1
```

必须先跑一遍 `action=login`，否则会在第 2 步停下报「没登录」。
这不是失败，是提醒你去扫码。

**各平台独有的坑**（都是实测）：

- **抖音**：上传框是隐藏 input，只能走 `DOM.setFileInputFiles`；转码最长 8 分钟；
  标题超 30 字前端静默截断；会弹「推荐封面」挡住发布按钮，脚本会自动选第一张。
- **小红书**：必须先切「上传视频」tab；转码最长 10 分钟（比抖音还慢）；
  正文是 quill 编辑器；**手打 # 不会变成真话题**，话题要从容器里选。
- **视频号**：入口在 `/platform/post/list`，要先点「发表视频」；
  登录态 7 天过期，是全平台里最需要重登的。
- **B站**：网页版上传慢，有 biliup CLI 的话更快（但那要另装 Rust 工具）。

## 四、排期与通知

```
publish_center action=queue_add content=工程名 platform=douyin at="2026-11-16 09:00"
publish_center action=queue_due          # 看现在该发哪些（带 overdue_min）
publish_center action=queue_mark id=… state=done url=…
```

排期是「提醒你该发了」，不是「到点自动发」。自动发要无人值守地握着登录态跑，
风险比收益大 —— 出了事（错内容、错账号）没法在中途拦。

通知支持飞书/钉钉/企业微信/Telegram/Slack/通用 webhook。
钉钉要加签，`secret` 传给 `channel_set`，加签由脚本做，不用你算。
**通知失败只返回 ok=false，不抛异常** —— 通知发不出去不能拖累发布本身。

## 五、归因：发完之后哪条真有效

```
analytics action=report                     # 四维总览
analytics action=by_time                    # 什么时段发最好
analytics action=by_tags                    # 哪些话题带量
analytics action=update platform=douyin title=… data={"view":1200,"like":35}
```

规则三条，别越界：

1. **样本少于 3 条不下结论**（`MIN_SAMPLE=3`）。一条数据的「规律」是噪音。
2. **没填播放数的不参与统计**。填 0 会污染分位数 —— 0 播放和「没查」是两件事。
3. 用**中位数**不用均值。一条爆款会把均值拉飞，中位数才反映常态。

看到 `reliable=false` 的桶，就当参考，别当成结论去指导排期。

## 六、一条完整的活长什么样

```
1. hotspot action=ideas keywords=你赛道 n=3        → 挑一条
2. 按「有具体的人 / 有冲突 / 你能补一层」过滤       → 定题
3. 写文案 → 出片（走剪辑那条线）
4. publish_center action=check                     → 改到合规
5. publish_center action=run exec=0                → 看截图，给用户确认
6. publish_center action=run exec=1                → 真发
7. analytics action=update data={...}              → 24 小时后回填
8. analytics action=by_time / by_tags              → 下次调整策略
```

第 5 步到第 6 步之间**必须有人看过**。跳过这一步，就是把没检查过的内容直接发出去 ——
而发出去撤不回来。
