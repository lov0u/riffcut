# 高光切片与跟随运镜

两件事，都靠 ffmpeg 一个滤镜族做，不装 librosa 也不装 face_recognition：

- **高光切片**：听声音找精彩段。人激动时声音会响、语速会快，这是最便宜的判据。
- **跟随运镜**：看画面左右谁更亮，判断谁在说话，横版转竖版时窗口跟着人横移。

## 零、先判断该不该用

| 你的素材 | 用什么 | 别用什么 |
|---|---|---|
| 直播回放、访谈、口播原片 | `highlight pick` 挑段 + `cut` 切出来 | 不要指望它挑出「金句」，它只认响度 |
| 双人访谈、连麦、播客 | `highlight speaker` 判人 + `follow` 出竖版 | 单人镜头不要用 follow，它会把画面无故晃 |
| 已经剪好的成片要转竖版 | `follow` 或已有的 `vertical` | 只是裁中间就直接 `vertical`，别开跟随 |
| 音乐视频、无人声素材 | 都不适合 | 没有声音能量差异，也没有人脸位置 |

**三条硬边界**：

1. **高光按响度找，不按内容找。** 一个人平静地说出关键结论，声音不响，它挑不出来。反过来咳嗽、拍桌、笑声会被当成高光。所以 `pick` 出来的每段都带 `reason`（"比全片基准响 3.6dB，持续 2.0 秒"），先看 reason 再决定用不用。
2. **说话人按画面亮度判，不是人脸识别。** 前提是「说话的人脸更亮」（正对灯、离镜头近、在动）。逆光、两人亮度接近、戴帽子遮脸都会判错。判错的信号是 `probes` 里 `peaky: false` —— 那说明画面很平，这时它已经退回默认位置，不要硬改。
3. **跟随运镜会重编码画面。** 音频是 copy 直通的，画面必须重编（crop 的位置逐帧变，没法流拷贝）。所以慢，10 分钟片子要几分钟。

## 一、高光切片三步

### 第一步：摸底

```
action=probe  path=原片.mp4
```

看三件事：有没有声音轨（`has_audio` 为 false 就别往下走）、时长、画幅。

### 第二步：让它挑

```
action=pick  path=原片.mp4  n=3
```

参数怎么给：

- `n` 默认 3。挑太多没意义——高光的定义就是「少」。
- `min_dur` / `max_dur` **留空**。留空会按片长自适应：最短 `max(1.2, min(6, 片长×5%))`，最长 `max(6, min(45, 片长×25%))`。手填固定 3 秒，10 秒的短视频就等于要求单段占 1/3，什么也挑不出来。
- `sensitivity` 默认 0.45。挑得太杂就调到 0.6，挑不到就降 0.3。

返回每段带 `start` / `end` / `score` / `lift` / `reason`。**先读 reason**：
「声音比全片基准响 3.6dB，持续 2.0 秒」是人话，能判断；「score 4.2」不能判断。

### 第三步：切出来

```
action=cut  path=原片.mp4  segments=[{"start":2.0,"end":4.0},{"start":8.0,"end":9.5}]
```

默认重编码（`reencode` 走 libx264 crf20）。**不要图省事用流拷贝**——`-c copy` 会因关键帧对齐把切点漂 1-2 秒，切出来的段头尾都带别人的话。

切出来的文件落在成片目录，文件名 `高光-01.mp4` `高光-02.mp4`。

## 二、跟随运镜三步

### 第一步：看它判出几段

```
action=speaker  path=访谈.mp4
```

返回 `segments`（每段 `start` / `end` / `speaker` = L 或 R / `conf` / `dur`）和 `flips`（换了几次人）。

**关键看 `note` 那句话**：

- 「只有一个说话人……不建议做跟随运镜」→ 停，别做。做了会让画面无故左右晃。
- 「每分钟换 12 次以上，太碎了——多半画面太暗或两人位置不规则」→ 也停，改用 `vertical` 裁中间或者手工定几个关键点。
- 「很稳，适合做跟随运镜」→ 继续。

### 第二步：看它把人定位在哪

返回里的 `face_x` 是它估的人脸横向位置（0-1），`probes` 是逐条亮度：

```
"probes": {"L": {"x": 0.185, "bands": [89,122,82,43,43,43,43,43], "peaky": true},
           "R": {"x": 0.815, "bands": [43,43,43,43,43,82,122,89], "peaky": true}}
```

**必须按段取样，不能拿整片平均。** 双人一左一右，整片平均会得到「中间」，窗口切过去两个人都在边缘——等于白做。这也是为什么它是每段单独探一次。

`peaky: false` 说明最亮条与次亮条只差一点，画面很平，这时它保留默认 0.25/0.75，不要手改。

### 第三步：出片

```
action=follow  path=访谈.mp4  aspect=9:16
```

产出 `访谈-跟随9x16.mp4`。窗口宽按 `画高×9/16` 算（1080 高 → 608 宽），切点前后 0.35 秒线性过渡。

**想先看表达式再决定**：`action=pan` 只返回 ffmpeg 的 crop x 表达式，不渲染。表达式长这样：

```
if(lt(t,3.825),51,if(lt(t,4.175),51+(1210)*(t-3.825)/0.35,1261))
```

读法：3.825 秒前 x=51；3.825→4.175 秒从 51 线性走到 1261；之后固定在 1261。

## 三、串起来用

完整流程（八步）：

1. `probe` 摸底看有没有声音
2. `pick` 挑 3-5 段高光
3. 读每段 `reason`，删掉明显是咳嗽/笑声的段
4. `cut` 切出来
5. 对每条切片 `speaker` 看是不是真的两人对话
6. 是 → `follow` 出竖版；不是 → `vertical` 直接裁
7. 出片后跑 `gate` 体检（`highlight` 只管找段，不管成片质量）
8. 要发就交 `publish_center`

## 四、踩过的坑

- **ffmpeg 的 `-vf` 里不能直接写全角标点**。表达式里的逗号会被 ffmpeg 当成 filter 分隔符，所以 `pan` 返回的表达式必须整体用单引号包起来塞进 `crop=w:h:'表达式':0`。
- **`pts_time` 行与 `YAVG` 行是交替出现的**，必须按顺序配对。只扫 `YAVG` 会把时间戳全丢掉，整条曲线偏一个采样周期。
- **`-inf` 帧要跳过不能当 0**。全黑帧的 RMS 是 `-inf`，当 0 处理会让那一格变成「极响」，直接造出一个假高光。
- **爆音会让 pick 挑到广告**。片头片尾的转场音效通常比人声响，`pick` 会优先挑到它。切之前看一眼 `start` 是不是在 0-2 秒。
- **`follow` 对已经竖版的片子返回 `0`**。不是 bug：输出宽等于原宽，没有可移动的空间。
- **画面里有字幕条/台标时亮度会失真**。台标一直在那个位置，那条 ROI 恒定偏亮，`face_x` 会被拉过去。这种情况手工指定 `speaker_x`。
