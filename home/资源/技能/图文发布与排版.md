# 图文发布与排版

## 零、先判路：这三个平台各有各的走法

| 平台 | 走什么 | 需要什么 | 能到哪一步 |
|---|---|---|---|
| 公众号 | **官方 API**（`api.weixin.qq.com`） | AppID + AppSecret，且本机出口 IP 在后台白名单里 | 建草稿 → `exec=1` 才真群发到读者 |
| 头条号 | **浏览器 CDP**（`mp.toutiao.com`） | 扫码登录一次，状态留在独立 profile | 自动保存草稿 → 点「预览并发布」 |
| 抖音/小红书/快手/视频号/B站 | 浏览器 CDP | 各自扫码登录 | 见「热点选题与发布」 |

**公众号优先走 API，不要走浏览器**：公众号后台编辑器是 iframe 富文本，脚本塞字极不稳；
官方 API 只要 token 对，一次成功。代价是必须先在公众平台「设置与开发 → 基本配置」
把**本机出口 IP** 加进 IP 白名单，否则所有接口返回 `40164`。

不知道本机出口 IP 是多少？`publish_center action=wechat_status` 会直接告诉你 ——
它就是拿这个 IP 去请求的，报出来的就是微信侧看到的那个。

## 一、公众号：四步走，不许跳

1. `action=wechat_status` —— 先看配没配。返回 `has_file:false` 就是还没写配置。
2. `action=wechat_save app_id=wx... app_secret=...` —— 写进 `数据/配置/公众号.json`（chmod 600）。
   也可以让用户在文件里手填，或设环境变量 `WECHAT_APPID` / `WECHAT_SECRET`（环境变量优先）。
3. `action=wechat_publish markdown=... title=... cover=封面图绝对路径`
   —— **不加 exec 就是建草稿**，用户在公众号后台「草稿箱」里能看到、能改、能自己发。
4. 确认要发才加 `exec=1` —— 走 `freepublish/submit` 提交群发，然后轮询到有结果。

**四条硬约束，违反了就是白跑：**

- **封面必填**。公众号草稿接口强制要求 `thumb_media_id`，没封面直接拒。
  封面图超 10MB 会被拒；正文图超 1MB 会被拒 —— 先压。
- **标题 ≤64 字、正文 ≤20000 字节（不是字）**。中文一个字 3 字节，20000 字节约 6600 个汉字。
  超了 `build_article()` 直接抛，不会发出去半截。
- **草稿创建绝不重试**。`draft/add` 是有副作用的接口，超时了不知道建没建成，
  重试会在草稿箱留两篇一样的。所以超时一律抛 `DraftUnknown`，让用户自己去草稿箱看一眼。
- **正文图必须传成微信的 CDN 地址**。你写的 `<img src="/Users/...">` 或 `http://别的站/a.png`
  粘过去读者看不到（微信会拦外链图）。`wechat.publish()` 会自动把本地图走
  `/media/uploadimg` 传上去换成 CDN URL，所以**图要给本地绝对路径**，别给外链。

返回码要认得几个：`40001` token 失效（自动重取）、`40013` AppID 错、`40125` AppSecret 错、
`40164` **IP 不在白名单**（最常见，去后台加 IP）、`45009` 当天接口调超限、`48001` 没这个权限（号没认证）。

## 二、排版：gzh 干的事，以及为什么必须用它

**不要自己写 HTML 塞进公众号。** 微信编辑器粘贴时会剥掉 `<style>`、`<div>`、`class`、
`position`、`grid`、`float`、CSS 变量、外部字体、`backdrop-filter` —— 你精心排的版粘过去就是
一堆没有样式的黑字。

`gzh.convert()` 的出口保证三件事：

1. **样式全内联**（`style="..."` 写在每个标签上，不靠 class）
2. **每个文本节点都包 `<span leaf="">`** —— 这是公众号编辑器认的锚点，不包的话
   它会把整段当纯文本重排，字号行距全丢
3. **不用** `<style>/<script>/<div>/<link>/class=/id=/position/float/@media/@keyframes/
   @import/display:grid/var(--)/外部字体/backdrop-filter`

用法：

```
publish_center action=gzh_convert markdown="<整篇 md>" theme=ink
publish_center action=gzh_convert path=/绝对/路径/文章.md theme=ink preview=1
```

返回里 `check` 字段就是自检结果：`ok` 为真才算能粘。`leaf` 是包了几处，
`bare` 是漏网的裸文字（必须是 0），`half` 是中文里混了半角标点（只是提醒，代码块内不算）。

三套主题，都走「一篇文章只有一个强调色」，不搞渐变不搞玻璃拟态：

- `ink`（墨色，默认）—— 白纸 + #2b2b2b 墨字 + 朱红 #b23a2e 强调
- `plain`（纯黑白）—— 正式、通告、学术
- `warm`（米色）—— #faf7f2 纸面 + 深褐 + 铜金 #a8763c，适合生活/文化类

行内标记（写 md 时直接能用）：`==黄底==`、`++蓝底++`、`%%粉底%%`、`&&绿底&&`、
`!!红字!!`、`@@蓝字@@`、`^^橙字^^`。**一篇文章里高亮不要超过三处**，多了等于没有高亮。

`preview=1` 会生成一个带「复制到公众号」按钮的预览页，本地图自动内联成 base64
（不内联的话粘贴后回源抓不到就是裂图）。按钮走 `navigator.clipboard` 写 `text/html`，
所以复制出来是带格式的，粘进公众号编辑器直接成型。

## 三、头条：浏览器那套，坑都在细节里

```
publish_center action=toutiao_login                        # 先看登没登
publish_center action=toutiao_publish markdown=/路径/a.md   # 不加 exec = 存草稿
publish_center action=toutiao_publish markdown=... exec=1   # 真发
```

**头条没有「存草稿」按钮。** 草稿是编辑器自动保存的，所以 `exec=0` 的做法是：
把标题正文图都填好，然后**不点任何按钮**，等自动保存的接口回执。用户去「内容管理 →
草稿箱」就能看到。

**四个坑，全是真机踩出来的：**

1. **正文图必须走工具栏上传**。ProseMirror 会把 `<img src="本地路径">` 直接清掉。
   正确流程是点工具栏「图片」→ 面板里塞文件 → 等缩略图出现 → **点「确定」**。
   漏掉「确定」那一步，图只停在素材选择区，编辑器里一张都没有 —— 这是最容易
   发出去一篇「以为有图其实纯文字」的原因。所以 `toutiao.publish()` 里
   插图失败会把失败列表返回来并**阻断发布**，不要绕过这个阻断。
2. **话题要先打 `#` 等联想面板出来，再打话题名**。一次性插 `#话题` 字符串不唤联想，
   实测无效。匹配上之后判据是编辑器里 `a.tteditor-forum` 的数量 +1。
   匹配不上要按 `len(tag)+2` 次 Backspace 把半截井号删干净，否则正文里留个孤零零的 `#`。
3. **话题要在封面前填**。封面上传会抢焦点，之后打的字进不去编辑器。
4. **发布结果不看页面提示，看接口回执**。头条点完「预览并发布」页面不一定跳转，
   靠 toast 判会漏判。`_wait_receipt()` 监听 `POST mp.toutiao.com/.../article/publish`，
   2xx + `code/err_no/errno/errcode` 全 0 + 返回里有 `article_id`/`pgc_id`（纯数字且 >0）
   才算真发成功。其它一律当 unknown，去「内容管理」自己确认。

`TITLE_LIMIT = 30`，`TAG_LIMIT = 5`。头条自动取正文首图当封面，所以**首图要挑好**，
或者在正文最前面放你想当封面的那张。

## 四、卡片成图质检：card_audit 查什么

自动化出的卡片图最容易犯的错不是丑，是**空**：内容堆在上半截，下半截一大片死白。
`card_audit` 用「横向边缘密度」判空 —— 文字和图形有边缘，纯色和平滑渐变没有，
这比「和背景色比差异」稳得多（渐变背景也能正确判空）。

```
publish_center action=card_audit path=/绝对/路径/卡片.png
publish_center action=card_audit dir=/某个文件夹 pattern="*.png"
```

返回六个指标，判定看这四条：

- `bottom_dead > 0.15` → 底部死空白（画幅没填满，最刺眼的廉价感）
- `max_gap > 0.15` → 中段有大空洞（要补内容或换骨架）
- `span < 0.80` → 内容纵向跨度不够（没铺满画幅）
- `bands[3] < 0.10 且 bands[0] > 0.30` → 头重脚轻（内容全在顶部）

`pass` 为假时 `hint` 会给一串可执行的修正阶梯，按顺序试：加大字号 → 加高行距 →
补一条分隔或小字注 → 换更满的骨架。**不要靠加装饰图形填空白**，那只是把死白变成噪音。

`tol` 默认 12（边缘阈值）。深色底、低对比设计可以调到 18；极简白底细字可以调到 8。

## 五、一条图文的完整流水线

1. `hotspot action=ideas` 拿选题（或用户直接给题）
2. `action=board` 看这个选题在几个平台的热度，判断值不值得写
3. 写稿（`write` 工具落成 .md）—— 标题控制在 30 字内，头条公众号两边都能用
4. `action=card_audit` 检查配图（如果是程序生成的卡片）
5. `action=gzh_check` 自检排版（先 `gzh_convert` 拿 HTML 再 check）
6. 公众号：`wechat_publish`（不加 exec 建草稿）→ 用户看 → 加 exec 群发
7. 头条：`toutiao_publish`（不加 exec 存草稿）→ 用户看 → 加 exec 真发
8. `action=record` 记一条发布记录；过一天 `analytics action=update` 回填数据

**第 6、7 步之间不要连着做。** 两个平台的读者群完全不同，同一天群发两处等于自己分流。
先用一个平台试水，数据回来了再决定另一个发不发、怎么改标题。
